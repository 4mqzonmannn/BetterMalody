# スペクトログラム(波形ビジュアライズ)メモ

## 何を見ているか
- **スペクトログラム** = 音を短い窓(数十ms)ごとに周波数分解(STFT)し、「時間 × 周波数」を平面に、**強さを色**で描いたもの。
- REAPER のスペクトログラム表示 = 横が時間・縦が周波数(低音が下)。Malody は時間が縦に流れるので **縦=時間 / 横=周波数(左=低音, 右=高音)** に回転して重ねる。
- 色は強さ(dB)。暗い(黒〜紫) → 赤 → 橙 → 黄/白 の順に強い。

## 譜面制作での使い方
| 見え方 | 意味 | 譜面での使い道 |
|---|---|---|
| 横方向の明るい帯(全周波数が一瞬明るい) | ブロードバンドな打撃(キック/スネア/ハット等)=トランジェント | **アタック位置の特定**。ノーツを置く位置の目印。拍線とズレていれば offset/BPM の誤差 |
| 縦方向の細い明るい線 | 持続する音程(メロディ/ベース/ボーカル/シンセ) | 長音(ホールド/スライド)の始点・終点、メロディの上下動(左右のレーン配置)の参考 |
| 斜めの線 | 音程が上がる/下がる(グリッサンド、ライザー) | スライドの軌道(Slide/Wipe)の参考 |
| 帯の幅・位置 | 楽器の音域(キック=左端付近 / ハット=右端付近) | **楽器ごとにレーン/担当を割り当てる**(低音=左、高音=右) |
| 全体の明るさ・密度の変化 | セクション境界、ブレイク、ビルドアップ | 譜面の密度や演出の切り替え位置 |
| 無音(暗い)区間 | 休符・ブレイク | 休符の位置確認、空白を作る区間 |
- **BPM/オフセット検証**: 強いトランジェントが拍線(補助線)の上に揃っていれば合っている。少しずつズレていくなら BPM 誤差、一定量ズレているなら offset 誤差。
- **聞き分けにくい音の可視化**: 密集した音の中の特定楽器の位置が目で追える。

## 画像(スクショ)の読み方
- 左の数字(138/139/140、74/75)= 拍番号(Malody の拍ラベル)。拍線ごとに明るい横縞 = 4分の打撃。
- 左側の暗い縁 = 低周波数(超低域は暗いことが多い)、右へ行くほど高周波。色の濃い帯は音の主成分。
- 丸/四角のノーツは、強いトランジェントや音程の上に置かれている(音に沿って置いている例)。

## 実装方針(BetterMalody への落とし込み)
1. **データ生成**(オフライン or アプリ内)
   - 譜面の音源(.ogg)をデコード → mono → STFT(窓 2048 / hop 256〜512 / Hann) → 振幅を dB 化 → **メル/対数周波数**へ圧縮(横幅 = 64〜128 ビン程度)。
   - 時間は **ms 基準**で計算し、表示時に BPM 変化(BPM リスト)で拍位置へ再サンプリング(Malody のエディタ y は拍に比例)。
   - 色は固定カラーマップ(例: 黒→紫→赤→橙→黄)。強さは dB クリップ(例: -80〜0dB)。
2. **描画**
   - 縦に長いテクスチャは分割(例: 512〜1024px ごとのタイル)して、ノート用コンテナ(editor+1472)の背面に子として追加。
   - 現在位置に合わせたスクロールは、ノートと同じ親ノードに入れれば自動で追従する。FX プレビュー(G による歪み)中は、タイルの y を G で再配置する。
   - 透過度を設定可能に(ノーツ・補助線が見えるように 30〜60%)。
3. **操作(OS 依存なし = ゲーム内メニュー)**
   - 「その他」に Spectrogram ON/OFF、濃さ(透過)、周波数スケール(リニア/メル/対数)、感度(dB 範囲)。
4. **性能**
   - 事前計算 → `Documents/<曲>/<譜面>/spec.png`(タイル)などにキャッシュし、再起動後は読み込みのみ。
   - 5 分の曲で、横 128 × 縦(時間)約 3.6 万行(hop=512@44.1k の場合 約 2.6 万フレーム)= RGBA で約 13MB。タイル化と間引きで調整。
5. **調査項目**
   - ゲームの OGG デコーダ(stb_vorbis / FFmpeg 系)を呼べるか、dylib 側に軽量デコーダ(stb_vorbis 単体、約 3k 行)を同梱するか。
   - cocos2d の Texture2D を生ピクセルから作る関数(Texture2D::initWithData 相当)のアドレス特定。
   - Slide エディタ(横幅の使い方が異なる)での対応。Key(レーン数に応じた帯)との見せ方。

## 参考(用語)
- **STFT**: 短時間フーリエ変換。窓長で「時間分解能」と「周波数分解能」がトレードオフ(窓が長い=音程がはっきり、時間がぼやける)。
- **メルスケール**: 人間の聴覚に近い周波数軸(低域を細かく、高域を粗く)。
- **ソナグラフ(sonogram)** とも呼ぶ。REAPER は「Spectrogram」ビュー(波形の表示切替)。

## 試作(2026-10-15): tools/spectrogram.py
- 実行: `python3 -I tools/spectrogram.py <ogg> <mc> <out.png> [--beat0 B --beats N --rpb 行/拍 --bands 96]`(依存: numpy / PIL / ffmpeg)。
- 処理: ffmpeg で mono 44.1kHz へデコード → STFT(窓 2048, hop 256, Hann) → 対数周波数 96 帯(50Hz〜14kHz。帯内に複数ビンがあれば最大値、無ければ補間 = 低域の欠け防止) → dB → 70dB レンジで正規化 → 黒→紫→赤→橙→黄白。
- 時間→拍: .mc の `time`(BPM リスト) と sound の `offset` から、拍 b の時刻 = offset + Σ(拍長)。1 行 = 1/rpb 拍へ再サンプリング(行が複数フレームにまたがるときは最大値)。向きは Malody と同じ(時間が上へ進む)。
- `offset check`: スペクトルフラックスの強いアタックと 1/4 拍グリッドの時刻差(ms)を集計。+ = 音がグリッドより遅い。
  - mourning(offset 550ms)の結果: 拍 0〜200: 中央値 +7.3ms / 200〜500: +8.1ms / 640〜760: +5.3ms(σ≈14ms)。→ 譜面は音に対して概ね +6〜8ms の遅れ(オフセットを約 -7ms 調整すると揃う)。
- 出力例: `work/spectro/mourning_zoom.png`(拍 640〜648)、`mourning_overview.png`(全曲 6 行/拍)。

## 方針(ユーザー要望 2026-10-15)
- **レーン上に薄く重ねる**: エディタのレーン領域(Key: レーン左端〜右端 / Slide: xwidth)に、周波数を横方向に引き伸ばしたテクスチャを、**半透明(20〜40%)でノートの背面**に敷く。横方向 = 周波数(左=低音)。
- ノート・補助線・拍番号は、そのまま上に表示。ON/OFF と濃さは「その他」メニュー(ゲーム内)。
- 実装順: ① ゲーム内の OGG デコーダの有無を確認(バイナリには vorbis のコード=libvorbis/tremor 系あり) → ② デコード+STFT を dylib 内で実装(Accelerate/vDSP の FFT が使える。ライブラリ追加は不要) → ③ 拍ごとのタイルを RGBA で作り、cocos のテクスチャ生成関数で Sprite 化(or 一旦 PNG をキャッシュし、ゲームの画像ロード関数で読む) → ④ editor+1472 の背面に追加、zoom/preview(G)で y 再配置。

## 実装メモ(アプリ内, 2026-10-15)
- 生成: ogg → stb_vorbis(`dylib/vorbis_impl.c`, `vorbis_api.h`) → mono → STFT(2048, hop≈5.8ms, vDSP) → 対数96帯 → dB → 70dBレンジで 0..255 量子化。計算は背景スレッド(mourning 215秒で約0.35秒)。
- タイル: 16拍×16行/拍 = 96×256 RGBA を Texture2D(`new 0x30` + ctor `sub_1005783E8` + `sub_100578504(tex,&{ptr,len},1,2=RGBA8888,w,h)`)にして、Sprite(`new 0x3E0` + ctor `sub_10056ADCC` + vtable+1344 `initWithTexture`)へ。★`sub_10056CB50` はバッチノード(単体スプライトではない)。
- 配置: editor+1472(ノートコンテナ)の子、zOrder=-100。位置 x=レーン左端, y=K*(G(beat)-gG0)-off、サイズは `sub_10054471C(sp,w,h)`(scale 設定)。画面付近のタイルのみ生成(1フレーム2枚まで)。
- 時間: BPM リスト(outer+584)の拍と拍長から積算 + .mc の sound offset。譜面パスは outer/editor 内の std::string を走査して取得。
- 落とし穴: 色LUT(`spec_init_lut`)の初期化忘れで全画素が透明になった(texture ok=1・glname 有効でも見えない)。
